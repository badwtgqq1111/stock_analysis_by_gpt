# Transformer 样本外评估与性能优化规划

> 状态：P0.1/P0.2 已完成。已完成时序特征对上限、均衡窗口抽样、懒加载 batch、运行进度和折内测试段批量序列推理；待完成 OOS manifest 扩展与多年面板评估。

## 目标

建立一条可复现的 A 股横截面时序 Transformer 研究路径：避免未来函数，以合理成本得到可与 LightGBM 比较的样本外 RankIC、IR、组合净收益和回撤。

`--stage transformer` 与 `--stage oos_predictions` 职责必须分离：

| 阶段 | 目的 | 频率 | 是否重训 |
|---|---|---|---|
| `transformer` | 训练和保存当前生产模型 | 月度或每 20 个交易日 | 一次 |
| `model_scores` | 用保存模型对最新截面评分 | 每交易日 | 否 |
| `oos_predictions` | 验证历史上未知日期的真实预测能力 | 研究/发布前 | 每个折一次 |
| `model_comparison` | 消费 OOS 预测，输出模型比较 | 每次 OOS 后 | 否 |

OOS 不能复用生产最终模型。生产模型包含截至当前日期的训练信息，拿它预测过去日期会导致未来数据泄露。

## 当前问题

当前清洗面板日志约覆盖 2025-09 至 2026-08，约一个交易年度。即使 OOS 配置请求 756 日，数据面板本身不足也只能生成约五个 20 日测试块。这只适合验证链路，不足以证明模型跨牛、熊、震荡市场有效。

原始时序实现还存在两个工程瓶颈：

1. 约千个原始因子连同缺失掩码会翻倍为两千余输入维度；60 日窗口和 20 万样本会产生数十 GB 至百 GB 的复制张量。
2. 对每个 OOS 决策日重复创建历史 as-of 面板和单独调用推理，时间随测试日期数线性放大。

## 设计原则

### 时间与 PIT

1. 每一折只能训练于测试开始日前可见的 `trade_date` 和 `available_at` 数据。
2. 标签 horizon 为 20 日时，训练/验证边界使用至少 20 个交易日 purge；内部验证也使用同样的 embargo 规则。
3. 特征选择、截面归一化参数、缺失处理和 scaler 均在该折训练可见数据内确定，并写入 manifest。
4. 行业、财务和另类数据继续按 PIT 合约过滤；缺失可保留 mask，不能用未来值回填。

### Qlib 式任务协议

采用“每折训练一次、整段测试批量推理”的滚动任务，而非每个测试日重训：

```text
fold 1: train -> valid -> purge -> test block
fold 2: expanded train -> valid -> purge -> next test block
fold 3: expanded train -> valid -> purge -> next test block
```

每个测试块只携带首日之前的 `lookback - 1` 日上下文，再加测试块全部交易日。对每个交易日独立做截面预处理，然后以测试日为终点构造序列；整个测试块通过 DataLoader 批量评分。该方式与按日期 as-of 评分信息集相同，但不会反复复制历史面板。

### 数据规模与模型预算

默认配置：

| 参数 | 值 | 目的 |
|---|---:|---|
| `lookback` | 60 | 保留约一个季度的交易日依赖 |
| `max_feature_pairs` | 128 | 每个 `*_clean` 因子保留同源 `*_is_missing` 掩码 |
| `max_samples` | 12,000 | 跨股票和时间均衡抽取训练窗口 |
| `prediction_stride` | 5 | 周度调仓研究；设为 1 才逐日评分 |
| OOS 折数 | 3 至 5 | 研究阶段的收益/成本平衡 |

时序特征在每折内按训练标签相关性、覆盖率、方差排序。该规则是模型训练的一部分，必须被记录并固定；不能用最终测试期结果挑选特征。

## 推荐评估层级

### P0 链路验证

- 3 至 5 个 expanding OOS 折。
- 每折只训练一次；测试段批量评分。
- 比较 LightGBM 与 Transformer 的 RankIC、RankIC IR、IC、IC IR、Top-K 净收益、最大回撤、换手和成交容量。
- `20d` 标签的重叠观察需在显著性分析中使用 block bootstrap 或 HAC/Newey-West 修正。

### P1 模型选择

- 将 clean panel 扩展到至少 3 年，优先目标为 5 年，覆盖多种市场状态。
- 最后 6 至 12 个月保留为冻结最终测试集，不能用于调参、选择特征数、决定模型权重或策略阈值。
- 开发期使用滚动训练/验证块决定超参数；最终测试集只运行一次确认。

### P2 生产更新

- 每 20 个交易日或每月执行增量微调/重训；每日只执行 `model_scores`、`selection` 和纸面账户更新。
- 后续折可以从前一折模型 warm-start，再只学习新增训练日期；前提是特征契约、架构、数据版本固定，且任何当前测试日期不进入该折训练。
- 模型权重只根据已成熟 OOS 与纸面结果更新，不根据单次选股名单人工调整。

## 实施任务与验收

| 优先级 | 任务 | 验收 |
|---|---|---|
| P0.1 | 限制时序特征对、均衡采样、懒加载 DataLoader | 训练不复制完整张量；日志显示特征数、样本数和 epoch |
| P0.2 | 测试块批量序列构造/推理 | 一个折只调用一次 Transformer 评分；输出日期严格等于采样测试日 |
| P0.3 | OOS manifest 增加特征/样本/stride/测试块元数据 | 可复现每折模型与评分日期 |
| P1.1 | 多年 clean panel 与冻结测试期 | 覆盖报告明确训练、开发 OOS、最终测试区间 |
| P1.2 | 重叠收益显著性与按市场状态归因 | 报告输出修正后置信区间及牛/熊/震荡分组 |
| P2 | 受控 warm-start、定期重训与模型监控 | 不引入测试期信息，模型版本可回滚 |

## 非目标

- 不将 FinGPT 的文本 LLM 微调流程当作量价因子横截面模型的验证协议。
- 不将 Kronos 等时序基础模型的零样本结果直接等同于本地 A 股选股收益。
- 不因加速而缩短 as-of 信息集、取消 purge/embargo 或使用最终模型回测过去。
