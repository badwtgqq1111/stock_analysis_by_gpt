# P1.22 CN 成交量单位、选股形态、端到端 OOS 与 SHAP 验收计划

状态：计划文档；**本文件不代表修复、回测或 SHAP 验收已经完成**。基准日：2026-09-23；编写日期：2026-09-24。
关联：[P1.19 数据卫生](P1_19_cn_data_hygiene_plan.md)、[P1.21 启动门禁](P1_21_startup_gate_robustness.md)、`config/cn_pipeline.toml`。

文档结构：**第一部分（§0~§8）为 2026-09-23/24 的原始计划与 P0 实施记录**；**第二部分（§9~§15，2026-09-26 合并）为本轮实测结论、优化/重构清单、因子挖掘与非 OHLCV 因子全量重评估规划、以及“每只股 100% 归因”的验收定义**。第二部分新增内容全部有对应证据目录与哈希，可直接复核。

## 0. 决策与边界

执行顺序固定为 **P0 数据单位修复 → P1 历史选股形态审计 → P2 完整策略 walk-forward A/B → P3 模型归因与 SHAP 验收 → P4 模型/特征方法对照**。P0/P2 通过前，不根据单日选股印象直接提高“刚启动”权重，也不把 PCA 当作默认优化方案。

当前生产由 LightGBM + Transformer 打分、启动门禁、信号 sleeve、预选、PK 与退出组成。模型 SHAP 只能解释 LightGBM **原始预测分数**，不能解释 Transformer、规则信号、百分位排名、PK 权重或最终交易收益。P1.21 的 `score`/`eligibility` 门禁及其历史 A/B 已存在；本计划不重复造一套同名门禁，而是在修复数据后用**相同完整策略口径**重验。

## 2. P0：成交量单位契约与受影响数据修复（最高优先级）

**范围与位置**：`data/ingest/providers/cn_history.py` 的腾讯/新浪/其他来源日线归一化，`data/store/warehouse.py` 的跨后端读取口径，`factor_engine/ml/panel_dataset.py` 的量价衍生特征，`test/test_ohlcv_quality.py` 及新增单位回归测试。

1. 写明 `volume` 的唯一仓储单位为“股”；源数据保留 `source`、原始单位判定与换算标记。先确认腾讯返回字段在不同股票上的单位语义，不能把所有腾讯记录无条件乘 100。
2. 对 `amount/(成交均价×volume)` 做约 1、约 100 和异常/无法判定三类审计。优先使用原始未复权价格或成交均价；停牌、零成交、价格异常及复权价跨期样本单列，不用硬阈值静默修正。对“手”单位按确定性规则换算为股，对模糊记录停止发布并输出代码/日期/来源。
3. 在**副本**上先修复受影响历史分区，比较 OHLC 及成交额哈希不变、成交量与标记变化，再原子发布；保留可回滚备份与修复清单。重建依赖成交量的 rolling 特征、clean panel；使用同一配置重训两模型，并重放 2026-09-23 选股。
4. 补源切换回归：股票日线单位为股、跨来源连续；`pv_volume_ratio_20d` 不再因换源出现虚假百倍断点；同一批复核股票的特征值可从原始 bar 复算。对全市场输出异常比例与剩余未决样本清单。

**P0 完成门槛**：影响记录及对应下游分区清单完整；确定性样本修复后约 100 倍单位异常归零；至少覆盖 `000721.SZ`/`000796.SZ` 的回归测试；旧/新面板与选股差分报告归档。若存在未决样本，不将其悄悄填成 0 或送入生产模型。

**预期产物**：单位审计 CSV/JSON、修复前后差分、数据/特征版本 manifest、回滚脚本、重训与 9/23 重放报告。执行代码时按原项目测试和回滚规范另建验证包；本计划文档本身不实施数据修改。

## 3. P1：将“高位回落/刚启动”变成可检验的标签

**分析对象**：每个历史决策日的全市场可投池、模型 Top-N、信号候选、PK 后持仓，分开计算**只数占比与持仓权重占比**，按牛/横盘/弱市及行业分层。只使用决策时点已可得的 OHLCV；量能指标待 P0 修复后才纳入。

预注册三类初始口径，阈值仅供第一轮审计，任何调参只能在训练窗口内进行：

- **回撤型**：近 20 日收益 < 0、收盘 < MA20、距近 60 日高点回落 ≥10%。单独报告距 252 日高点的距离，避免把“大幅回撤”误称为“当前高位”。
- **初启动 A（突破）**：收盘突破前 20 日最高价，同时近 20 日涨幅 ≤20%，用修复后的成交额/成交量确认而非仅凭单日涨停。
- **初启动 B（反转）**：5 日收益转正并从 MA20 下方上穿，近 20 日涨幅 ≤10%；与 A 分开评估，避免把反抽当突破。
- **其余/混合**：不满足以上条件的样本不强行归类；A/B 与回撤口径若重叠，按预定优先级拆开并记录冲突率。

**P1 完成门槛**：输出逐日 stock-level 标签与按模型腿/信号腿/最终组合的汇总；报告覆盖率、缺失率、各类持仓权重、5/10/20 日实现收益与成本前后分布；至少与 P1.21 既有 `score`/`eligibility` 门禁的输出对齐。此阶段只审计，不改生产选股权重。

## 4. P2：完整策略 walk-forward A/B，而非只比模型 Top-K

**基线冻结**：固定 P0 后的数据快照、模型训练代码与特征版本、现行 `score` 门禁、LightGBM/Transformer 权重、sleeve/预选/PK/退出参数。`config/cn_pipeline.toml` 默认关闭 `oos_predictions` 与 `model_comparison`；历史试验须显式运行并记录配置覆盖，不把单个模型的 OOS 表格当成最终组合收益。

**预注册对照臂**：A0 现行完整策略；A1 只增加 P1 形态诊断、不改变交易；A2 初启动候选独立小额度 sleeve；A3 初启动倾斜/过滤。A2/A3 不同时调模型、成本与风险参数；先评价 A2，只有它通过才评价更激进的 A3。P1.21 的 `score` 与 `eligibility` 作为分层/敏感性检查，不把已有回测重复计为独立样本。

**统一评价**：按时间扩展训练、purge/embargo 覆盖标签重叠；每个决策日重放当时可得的模型分数、可投池、强制信号、PK、资金预算与退出。按 T+1 可成交价、涨跌停/停牌约束、佣金、冲击和滑点计算组合净收益；给 15/25/50 bps 等成本敏感性，而非只给单一假设。报告 5/10/20 日和实际退出持有期的增量净收益、最大回撤、换手、持仓容量、行业/风格集中度及按市场状态拆分结果；多次试验数量一并登记。

**P2 上线门槛**：相对 A0，预先指定的主指标（扣成本后的风险调整收益）在**至少两个非重叠 OOS 时段**为正向增量，且最大回撤/容量未明显恶化；完整策略结果须可逐单复核。若未通过，保留 A0，不因“形态更像刚启动”而上线。

## 5. P3：CN 模型 SHAP 验收（解释，不是 alpha 证明）

1. 在 CN 生产评分链路接入 LightGBM `pred_contrib`，对**实际送入模型的已预处理特征**、原始预测分数和偏置项生成逐股贡献；同时写模型/特征 schema 哈希、交易日、候选来源与数据版本。转换成百分位分数后不再要求 SHAP 相加，因为百分位是横截面变换。
2. 覆盖模型候选与最终模型腿；信号 sleeve 标记为“规则解释”，Transformer 标记为“独立敏感度/替代归因”，不把 LightGBM SHAP 展示为组合总贡献。
3. 按特征族汇总 `mean(|SHAP|)`、加权绝对暴露及有符号暴露。当前 `summarize_shap_history()` 只取 `mean_shap`，正负可相消，漂移分析要补绝对值口径与跨模型版本可比性检查。
4. 运行时验证 `bias + ΣSHAP` 与**原始** LightGBM 预测逐行一致（预设绝对容差 1e-5，超出则失败）；结果文件非空，模型腿覆盖率 100%，历史至少三个相邻观察窗可复核。建立数据缺失/特征映射错误的显式失败路径。

**P3 完成门槛**：最新生产日 100% 模型腿有逐股可复算贡献；归因总和校验通过；模型与规则腿界线清楚；有跨期漂移报告。SHAP 达标只表示解释链路可信，**不表示收益或因子增量已经达标**。

## 6. P4：PCA / PLS / 原始因子模型的同场对照（新增）

### 6.1 判断原则与当前证据

- **不预设赢家**。PCA 是无监督方差压缩，不以收益为目标；PLS 利用标签但仍是线性压缩，必须在每个训练折内拟合；LightGBM 可以利用原始因子的阈值和交互，但冗余因子会增加搜索空间，使分裂重要性与相关特征的 SHAP 分摊不稳定。树模型不需要为了共线性而**必然**做 PCA，但也不能据此断言 PCA/PLS 一定降低收益。
- 不设“100～300 因子”硬上限，也不先按全样本单因子 IC 删除特征。弱单因子可能通过交互提供信息；预处理、筛选、聚类、PLS/PCA 的载荷和超参数，均只能由对应训练折及其内部验证数据确定。PCA 的 85%～95% 解释方差只能作诊断，不是收益验收阈值。
- 当前生产模型清单：LightGBM **1,249 列**（含清洗值与缺失掩码），Transformer **492 列**；`config/cn_pipeline.toml` 的 Transformer `lookback=60`，是时序序列模型，不是单日横截面“全因子直接灌入”。其生产配置 `max_feature_pairs=256`，OOS 配置为 128，应在比较报告中显式记录不同预算。
- 现有 `output/scratch_p1_17/profile_compare.json` 中 full/compact/core 的 RankIC 约为 **0.106 / −0.042 / −0.033**；它反对“先砍到很少因子即可提高收益”，却不能证明特征越多越好。`output/evaluations/cn_model_comparison.json` 的 5 折、20 个决策日，LightGBM / Transformer RankIC **0.0366 / 0.0291**；样本短，不能据此永久淘汰 Transformer。这两份产物的实验口径不同，不能互相充当同场 A/B。
- **优先修一个验证顺序问题**：`factor_engine/ml/model_training.py` 的 `_select_temporal_feature_pairs()` 使用标签相关性；`train_transformer_panel()` 目前先调用它、后做内部 `_purged_time_split()`。外层 OOS 测试折没有因此直接参与筛选，但内部验证折可能影响特征选择和 checkpoint 判断。把选择器移到内部训练折，再固定其选择去变换验证/测试折，补断言测试，之后才比较 Transformer。

### 6.2 预注册候选臂与实施顺序

| 臂 | 输入与模型 | 要回答的问题 |
|---|---|---|
| M0 | 修复 P0 后，现有清洗特征 + LightGBM | 当前基线；保留原始非线性与交互 |
| M1 | 相同 LightGBM，逐个特征族消融 | 哪一族有**样本外增量**，而非只看单因子 IC 或 SHAP 排名 |
| M2 | 仅用训练折相关性聚类/稳定性筛选后的 LightGBM | 去冗余是否改善稳定性、训练成本和净收益；保留簇代表的经济含义 |
| M3 | 相同输入上的 Ridge / ElasticNet | 透明、正则化线性基线；比较复杂模型是否真的有增量 |
| M4 | 训练折拟合的 PLS + Ridge（成分数内层选择） | 监督式线性压缩能否提高预测力 |
| M5 | 训练折拟合的 PCA + Ridge；PCA + LightGBM 作为可选单独臂 | 无监督压缩是否有价值；不得按解释方差直接宣布有效 |
| M6 | 修正内部特征筛选顺序后的 60 日 Temporal Transformer | 时序信息能否在计算成本、种子波动和最终组合净收益上证明增量 |

**实验隔离**：先修 P0 并冻结数据/标签/可投池；固定外层时间折、purge/embargo、预处理规则与成本模型；M1～M6 的特征筛选、聚类、标准化、PCA/PLS、成分数和模型超参数只在内层训练/验证中确定，外层测试折只做 transform/predict。保存每折特征列表、簇/载荷、模型 hash、随机种子和尝试次数。中性化作为可配置 A/B，不把“行业/市值中性化必须开启”当作无条件前提；应检查它是否抹掉可交易信号。

**两级评价**：先在相同 `forward_return_20d` 标签和相同交易日/股票交集上比 RankIC、Top-K 超额、跨市场状态稳定性及训练成本；候选通过后，再接入 §4 的完整预选→sleeve→PK→退出回放，比 15/25/50 bps 成本下的增量风险调整收益、回撤、换手和容量。相关特征之间 SHAP 排名可能重排，不以 SHAP 名次替代消融或净收益判断。

**P4 完成门槛**：M0～M4 的可复现实验、Transformer 验证顺序修复、至少两个非重叠 OOS 时段的配对对照报告均完成；M5/M6 作为挑战者，以净收益和稳定性决定是否保留。未胜过 M0 的方法保留为研究产物，不改生产模型权重。

## 8. 实施进度：P0 第一批代码与副本验证（2026-09-24）

### 9.14 关键读路径 bug：分组批读把“部分写的新批次”当成完整重写（2026-09-26，已修）

**症状**：2026-09-24 的 clean panel 里，`GTJA116_clean` 只有 **1,735 / 5,208** 只有值（9/18 是 4,994），
每只股票非空 `_clean` 列数中位 **83**（9/18 是 648），而 `pv_*`（面板侧现算）与 `moneyflow_*` 完整——
即最新交易日的横截面有 2/3 是空的。**但特征层里 9/24 的同一特征覆盖 ~5,200 只**。

**根因**：`ParquetDataStore.iter_frames_by_group_batches()`（clean panel 构建时读特征层用的就是这个）
为了省时间建了行组索引，并且假设“同一只股票最新一次 ingest 会完整重写它的全部特征”，于是
**只保留该股票 ingest 时间最新的行组、丢掉其余全部行组**。生产里存在多种**部分写**批次：

- RPS 步骤每次只写 `RPS_*`（每股 2~3 行）、时间戳最新；
- 修复/对齐重算只写最近 N 天；
- 成交量修复快照只写单个交易日。

一旦这些批次成为该股票的“最新 ingest”，它的**全部历史行组会被一起丢掉** → 面板读不到 GTJA116 等。

**证据**：同一个“缺失组”样本（300 只），用面板式宽日期范围读特征层：
修复前只拿到 **105/300** 只的 9/24 GTJA116，修复后 **299/300**。

**修复**（`data/store/parquet_store.py`）：读入所有命中 (股票, 日期范围) 的行组，以及“无统计信息”的
fallback 行组；重复值交给消费端 `build_feature_panel` 按 `(stock_code, trade_date, feature_name)`
依 `ingest_time` 取最新去重。代价是读取放大约 7~8 倍（面板构建变慢），**压实（R10）之后每个键只剩一行，
读放大自然消失**——所以 R10 从“省空间”升级为“修复读性能的必要步骤”。

**新增回归测试**：`test/test_feature_group_batch_read.py`（部分写的新批次不得挤掉更完整的旧批次）。

**影响与处置**：2026-09-24/25 那次生产选股是在这个“2/3 为空”的横截面上算出来的，名单不可信；
已用 launchd 一次性任务 `com.quant.cn-panel-rescore`（`scripts/run_cn_panel_rescore.sh`）重建面板并重新打分，
日志 `output/verification/cn_base_data_repair_20260926/panel_rescore*.log`。**在重建完成前不要依据当日名单交易。**

**顺带发现的同类风险**：任何“用 ingest 时间戳代表内容完整性”的假设都可能被部分写批次破坏
（本次是读路径）。建议在其它消费路径（`read_features` 的 order_by+keep-last、meta 层读取）一并复核。

## 11. 工作流 A：因子挖掘（替换“人工模板堆叠”）

### 11.1 现状问题

- 入模 1,284 列里，Alpha158/GTJA191/Alpha101 占 900 列、但单列 |IC| 只有 0.013~0.014（噪声底附近），且 136 个值列从未被任何一次分裂使用 → **模板堆叠产出的“数量”没有换来“信息”**。
- 这些库的因子互相高度相关（都派生自 OHLCV/VWAP 几个原语），树只需一列代表 → 冗余直接转化为训练成本与归因噪声。

### 11.2 目标与范围

- **范围**：OHLCV 基础数据（开高低收量额、复权因子）之外的**全部因子**都要重做评估；挖掘只生成“派生因子”，不引入新的原始数据源。
- **目标**：在相同标签/相同流程下，提高“新增因子对样本外净收益的边际贡献”，而不是提高 IC 名次。

### 11.3 设计（五段式）

1. **算子白名单 + 数据契约**：明确可用算子（Ref/Mean/Std/Corr/Rank/Delta/DELAY/Clip/条件表达式）、可用输入列（面板 683 列中经 R6 认证的子集）、输出必须 PIT 且带 `available_at`。
2. **目标函数（关键）**：挖掘内层评分必须与结算口径一致 —— 用**扣成本后的 RankIC / 净收益**（而非 `excess_return_without_cost`），并强制 purge/embargo。参见 §11.5 的反面案例。
3. **质量闸门**：复杂度（符号长度、基础特征数、自由参数比例、重复子树）、**冗余**（与已有因子相关性上限）、一致性（假设-描述-表达式对齐）、覆盖率（≥阈值）四类；不通过不入库。
4. **进化**：把“假设→表达式→评估→反馈”的**轨迹**作为进化单元（mutation/crossover），而不是只对表达式做局部改写；每轮记录血统（父代/变异点/评估结果）。
5. **折内选择**：任何基于 IC/相关性的筛选只在**内层训练折**拟合，外层测试折只 transform/predict（同时修掉 `_select_temporal_feature_pairs()` 的顺序问题）。

### 11.4 借鉴与不借鉴（QuantaAlpha 审阅结论，详见 `output/verification/quantaalpha_review_20260926/REPORT.md`）

- **可借鉴**：算子白名单 + 复杂度/冗余闸门 + 轨迹进化 + 因子库 JSON（血统+指标）；其“只用 6 个价量原语”的约束反而让它避开了我们这些稀疏数据源的坑。
- **不可照搬**：其 README 主表**只在 IC 维度最优**（0.0472 全场第一），策略维度落后于同表 TRA（ARR 6.81% vs 4.68%、IR 1.0502 vs 0.6453、MDD 8.51% vs 11.80%）；且在“同流程仅换因子源”的 8 行内 `corr(IC, ARR) = 0.027`——`Alpha158(20)` 的 IC 仅 0.0051 却有 ARR 4.63%。**它的 IRR 量级来自通用流程与期间 beta，不是因子挖掘的增量。**
- **必须避开的坑**：其挖掘内层用 `1day.excess_return_without_cost.*`（无成本）评估因子——这与我们“门禁内层无成本”是同一类错误。

### 11.5 验收门槛（工作流 A）

1. **M1 族消融**：全量 vs 去 GTJA191 vs 去 Alpha158 vs 去 Alpha101 vs 去全部三者，在固定数据/固定模型/成本口径下比较；只有净收益或风险调整收益为正增量才保留。
2. **两个非重叠 OOS 时段**：主指标在两个时段均为正增量，且回撤/容量/换手不恶化。
3. **账本与回滚**：每个新因子有血统与指标记录；可一键回滚到入库前状态。
4. **可解释**：新因子进入模型后，逐股 SHAP 能给出其对每只入选股的贡献（§13）。

### 13.1 归因链（8 层，逐层可复算）

5. **口径声明**：明确区分**决策归因**（100% 可复算，上行）与**结果归因**（“这只股赚了钱是因为哪个因子”属于分解而非因果，需另做反事实/消融，不承诺 100%）。

## 15. 2026-09-27 追加：因子 IC「显著性与有效性」协议（准入/淘汰的唯一裁判）

> 用户口径（本节的验收标准）：**主任务不是继续加因子或调门禁，而是保证因子 IC 的显著性（多重检验下仍然显著）与有效性（样本外、跨段稳定、方向明确、不冗余）。**

### 15.1 协议定义（脚本 `scripts/factor_ic_protocol.py`，输出 `output/research/factor_ic_protocol/`）

| 维度 | 做法 |
|---|---|
| IC | 逐日横截面 **Spearman（秩 IC）** → 月内均值；月 ≈ 20 交易日 ≈ 标签 horizon（接近非重叠） |
| 显著性 | 月度序列 **Newey-West(lag=1) t**（相邻月仍有重叠）→ p 值 → **BH-FDR q=0.05** 全列控制；同时报 Harvey-Liu-Zhu 门槛 t≥3.0 的通过率 |
| 稳定性 | 前半段 vs 后半段 IC 符号一致（`sign_stable`）、近 6 月是否同号、正号月占比 |
| 有效性 | `--oos-split` 把窗口切成"准入期/保留期"，只在准入期选列，再看保留期的符号与强度保留率 |
| 冗余 | 抽样 16 个交易日的横截面秩相关矩阵（Z^T Z/n）→ |ρ|≥0.9 并查集聚类，每簇只留 |ICIR| 最大的代表 |
| 数据质量 | 覆盖率、常量列、`_is_missing` 掩码列、估值 `age_td/is_stale/observation_coverage` 标为"质量列"，不参与准入 |
| 漂移监控 | 每次复跑与上一版 `factor_ic_admitted.json.prev` 对比，输出 `factor_ic_delta.json`（新增/淘汰/原因） |

**准入规则**：`|IC|≥0.02` 且 `|ICIR|≥0.30` 且 **BH-FDR 显著** 且 前后半段同号 且 是所在相关簇的代表；

### 17.2 合成腿的滚动非重叠验收（`scripts/composite_rolling_validation.py`）

口径：每 20 个交易日再平衡一次（= 标签 horizon，**窗口非重叠**）；每次只用**该日之前**的月度 IC
做准入与权重（walk-forward，无前视）；对照 = 同日随机 20 只 ×200 组；成本 = 与前次 Top-20 的换手 × 双边费率。

| 指标 | 值 |
|---|---|
| 再平衡次数（2025-09-01~2026-07-31） | 12 |
| 秩 IC（合成 vs 标签） | **+0.126，92% 的期数为正** |
| Top-20 超额 均值 / 中位 | **+1.098% / +0.220%**（20 日） |
| t | **0.97（不显著）**，胜率 50% |
| vs 随机（配对） | +0.326%，**t=0.15**，跑赢随机仅 50% |
| 平均换手 | **96.7%** |
| 扣费后（15/25/50bps） | +0.808%（t=0.72）/ +0.615%（t=0.55）/ +0.131%（t=0.12） |

**功效分析**：单期超额 std=3.91%、mean=1.10% → 要在同样均值下达到 t=2，需要 **≈51 个非重叠点（≈4.2 年）**。
即：**12 个点不足以判定头部有效**，但反过来也说明"头部选股在当前规模/持有期下统计上欠功效"。

### 17.3 结论：IC 有效 ≠ 头部可交易（这次是硬结论）

1. **因子与合成在横截面上确实有效**：IC 均值 +0.126、92% 期数为正、§15 的因子级 FDR/HLT 也都通过。
2. **但"从 5,000 只里挑 20 只"这一步没有通过验收**：12 次里 6 次跑输池均值，扣 25bps 后仅 +0.6%/20 日、t=0.55。
   逐次明细里可以看到典型情形：IC +0.076 而 Top-20 −3.07%（2025-12-02）、IC +0.160 而 Top-20 −1.74%（2026-03-06）。
3. 这不是"因子坏了"，而是**头部噪音**：20 只等权组合 20 日超额的 std≈3.9%，远大于均值 1.1%；
   换手 96.7% 又让成本吃掉约一半。

### 17.4 因此下一步要换方向（按性价比排序）

| 方向 | 做法 | 预期 |
|---|---|---|
| **A. 扩宽度** | 持仓从 6 只 → 20~30 只（一手约束下每只 700~2,000 元仍可下单） | 头部 std ≈ std/√(k/20)，t 按 √k 放大；是**唯一能直接提升统计功效**的杠杆 |
| **B. 拉长久期** | 标签/持有从 20 日 → 40~60 日，配合低换手 | 降低换手成本（96.7% → 目标 <40%）与再平衡噪音 |
| **C. 改成"倾斜"而非"选股"** | IC 用于在既有候选池（模型 Top-N ∪ sleeve）上排序/加权，不再用它从 5,000 只里挑 | 用 IC 的强项（横截面区分度）避开它的弱项（极值） |
| **D. 换标签** | 用头部相关的标签（top-decile 命中 / 路径分数 `path_score_20d`）替代"全截面分位" | 让训练目标与"能不能赚钱"对齐 |
| E. 加大测试样本 | 用重叠窗口 + Newey-West，而不是只等非重叠点 | 提升检测功效，但要承担自相关修正 |

**验收口径不变**（否则不上生产）：滚动非重叠 + 扣 15/25/50bps + **vs 随机配对** + 换手/容量约束；
任何"单窗口 t>3"的结论都必须先过 §17.2 这一关。

### 18.5 四条路线的总体结论

1. **A 是唯一被证实有效的方向**（宽度 ↑ → 均值/扣费后/t 都单调改善），但到 30 只仍然 t≈1.1，**不够**。
2. **B 需要更长的历史才能判**（现有 18 个月标签窗口对 40/60 日 horizon 只给 4~6 个非重叠点）。
3. **C 无增量**（池内倾斜 ≈ 池子本身）。
4. **D 是交换不是解决**（头部命中率 ↑、IC ↓、头部仍负）。
5. 合起来看：**横截面信号是真的（IC +0.11~0.17、92% 期数为正），但"从全市场挑最前面 6~30 只"这一步的
   噪音（20 日 std≈3.9%）始终大于信号（均值 1~1.3%）**。这不是模型选择问题，是**账户规模 × 持有期 × 头部宽度**的统计功效问题。

### 18.6 下一步（按"能直接改变功效"排序）

1. **把面板窗口 days 756 → 1500+**，重跑 §18.2 的 B（40/60 日），这是唯一能"增加样本而不是增加假设"的动作。

3. **降低换手**：现在 96~99%，把再平衡从每月改成每 2~3 个月（或分数做 5 日均值平滑），
   让信号的持续性替代高频换手。
4. 只有在 1~3 之后仍然不行，才去动模型/特征/标签——因为 §18.4 已经证明换标签救不了头部。

### 20.1 定案

1. **正交化（残差化）最优**，且在 k=50 上 t=3.17、13 期 100% 为正、扣 25bps 仍 +5.77%；
   k=20 时均值更高（+6.95%）但波动更大。**保留全池（5,141 只）→ 无宽度损失**。
2. **分组中性化（非参数）是稳健备选**：+3.82%/t=2.47。当暴露与收益关系非线性时优先它。
3. **硬筛池（B）表现最差**：入池数从 5,141 砍到 1,156（−78% 宽度），超额掉到 +0.12%/t=0.17。
   这同时验证了两件事：**(a) 筛池会损失宽度**（§18.1 已证宽度是有效杠杆）；
   **(b) 启动带里并不总是 alpha 所在**——它只是 0924 那一期的赢家形态。
4. **软倾斜（E，即现行门禁做法）不如正交化**（+3.27% vs +6.95%，t=0.89 vs 2.86）：
   把暴露直接加进分数会与 alpha 互相污染。
5. **结论（回答"哪种更符合量化专家风格"）**：
   - 风格暴露 → **横截面回归取残差**（或非参数分组中性化），交给"中性化"而不是"筛选"；
   - 硬筛只保留三类理由：**不可投**（ST/停牌/流动性/买不起）、**尾部风险**（如追高即失效的上界）、
     **合规或容量**；
   - 这样做还顺带修掉 §18.1 的宽度问题：正交化不砍池子。

## 22. 2026-09-28 综合结论与优化方向（量化专家 + 数学专家视角）

### 22.1 数学结构：我们到底在预测什么

1. **IC 是"秩的可预测性"，不是"收益的可预测性"。** 我们全程用逐日横截面 Spearman：
   `IC = corr_rank(score, r_{t→t+H})`。它约束的是**条件分布的位置排序**，不是期望收益。
   实证：同一套 90 列，
   - 标签 = 当日横截面分位 → IC **+0.113**（生产口径，正确）
   - 标签 = 原始收益 → IC **−0.032**（被厚尾支配，错）
   两者差 0.145，说明**目标函数的定义比特征工程更重要**（这也是 Gu-Kelly-Xiu / Feng-Giglio-Xiu 的核心提醒）。

2. **IC 高 ≠ 头部可交易**：IC 是整条分布的单调性度量；实盘只吃**上尾**。
   实测反例：准入模型十分位第 8 档 +1.61%、第 10 档只有 +0.62%（**上尾回落**）。
   数学上这对应"条件分布的上尾可分性"没有随 IC 一起提高。

3. **头部的噪声量级由 √k 决定（这是本题的"硬约束"）**：
   `σ(Top-k 等权 20 日超额) ≈ σ_single / √k`。实测 σ_single ≈ 15~20% → k=6 时 σ≈8%，k=20 时 ≈3.9%，k=50 时 ≈2.5%。
   而信号给出的均值差只有 1~6% → **在账户允许的 k 里，信噪比本来就在 1 附近**。
   功效分析（§17.2）：k=20、σ=3.9%、mean=1.1% 时，要 t=2 需 ≈51 个非重叠点（≈4.2 年）。

4. **Fundamental Law 视角（Grinold）**：`IR ≈ IC × √BR`。我们的 IC≈0.10 很高，
   但 4.5 万账户 + 6 持仓把 **breadth 锁死在 ≈6** → `IR ≈ 0.10×√6 ≈ 0.25`。
   这解释了全篇最反直觉的现象：**IC 一路提高，组合收益却不见得变好**——被 BR 卡住了。
   → 提升路径只有三条：**加宽 k**、**拉长持有期 H**（提高独立机会数）、**降低噪声**（成本/换手）。

### 22.2 因子层（结论扎实，可上生产）

- 90 列准入（|IC|≥0.02 且 |ICIR|≥0.30 且 **BH-FDR q=0.05** 显著 且 半段同号 且 相关簇代表），
  OOS 复核：**符号保留 98.0%、强度保留 86.9%** → 不是数据挖掘产物（HLZ t≥3 门槛也过 387 列）。
- **冗余是结构性问题**：1,366 列只有 **667 唯一列**、408 个相关簇、675 列 gain=0；
  实测 **20 列 > 1,256 列**（+0.1136 vs −0.0035）。这与 Kozak-Nagel-Santosh 的结论一致：
  在高维横截面里，**收缩/去冗余的边际价值高于继续加因子**。
- 直接效果：生产模型换成准入 90 列后，同切分验证 IC **0.0140 → 0.1414**（10 倍）。

### 22.3 组合层（本轮最硬的一击）

| 做法 | 数学形式 | 实测（13 窗口，扣 25bps） |
|---|---|---|
| 硬筛池后排序 | α 的**硬阈值投影**（丢宽度、丢连续信息） | +0.12% / t=0.17（入池 5,141→1,156） |
| 软倾斜（旧门禁） | α + λ·z(X)（信号与暴露互相污染） | +3.27% / t=0.89 |
| **正交化（已上线）** | **(I−P_X)α**（秩空间残差化） | **+6.07% / t=3.17 / 胜率 100%** |
| 只用模型分 | α | +1.92% / t=1.17 |

**门禁四分项的符号体检**（5,209 只截面）：`k_dist +0.310`（对）、**`k_high −0.371`（反）**、
`k_flow +0.117`（对）、`k_volume +0.040`（≈0）→ 加权合成后只剩 +0.079：
**一个反向项抵消两个正向项**。数学上，把符号不同的项放进同一个线性加权和，等于人为把信噪比压到最低。

### 22.4 优化方向（按"能否改变统计功效"排序，附数学理由与验证口径）

| 优先级 | 动作 | 数学理由 | 验证口径 |
|---|---|---|---|

   在宽度与久期无法扩展之前，继续堆因子/调模型的边际收益很低。

## 23. 2026-09-29 追加：策略注册表（回答"门禁分通道 = 两种策略吗？以后更多策略怎么办"）

### 23.1 结论：是的，本质是 N 个策略，不是一个门禁的两种参数

用户直觉正确。当前把"入场状态"塞进**一个全局标量门禁**（`startup_gate` 的 4 项加权和），
而模型腿与突破腿偏好的状态是**相反**的：

| | `dist_from_120d_low` | `dist_from_60d_high` | `volume_ratio_20d` | `flow_z` |
|---|---|---|---|---|
| **模型腿（低吸）** | 落在 0.05~0.30 带内（贴自身低位） | — | **≤1.2（缩量）** | ≥0 |
| **突破腿（donchian）** | — | **≥−5%（贴/破 60 日高点）** | **≥1.3（放量）** | — |

用一个线性加权和去同时拟合这两个相反的条件，数学上等价于**用同一个标量函数去逼近两个方向相反的
条件期望**——必然互相抵消。实测证据：`k_high` 的截面 IC 是 **−0.371**（方向错），
`k_dist +0.310` / `k_flow +0.117` 是对的，四项合成后只剩 +0.079（§19.3）。

### 23.2 目标架构

```
策略 = (signal 信号, state 状态/资格, sizing 仓位, exit 退出, budget 预算, evidence 证据)
组合层 = 在策略之间做预算分配 + 执行/风险约束（不再背负"入场状态"语义）
```

门禁从"全局标量"降级为**每个策略自己的一段 `state`**；`startup_gate` 只保留真正的
**硬护栏**（`hard_max_dist_from_120d_low` / `hard_max_return_60d`，属于尾随保护，不属于风格条件化）。

### 23.3 本轮已落地（零行为变更，先做治理与归因）

### 31.3 判据（"要不要为某个状态单独训模型"的三条件测试）

必须**同时**满足：

| 条件 | 判据 | 低位反弹状态当前值 |
|---|---|---|
| ① 状态有正 edge | 事件研究 20d 相对超额 > 0 且 t > 2 | ✘（−0.50%，t=−2.24） |
| ② 域内排序优于全域 | 域内模型 IC > 全域 IC | ✔（0.1375 vs 0.0769） |
| ③ 域内 Top-k 超额为正 | 域内 Top-k 相对超额 > 0（扣费后仍 > 0） | ✘（−1.47% / −1.97%） |

**①③ 都不满足 ⇒ 不值得为该状态训专门模型。** 条件②单独成立只会让人误判——
这正是"IC 高 ≠ 头部可交易"的又一次复现（§17.3 / §22.1 第 2 条）。

### 31.4 分工与价值排序（回答"模型 vs 信号函数"）

- **注册表里 `state` 与 `signal` 是正交字段**：`state`（规则）定义**在哪**，`signal`（模型或规则）决定**谁优先**。
  所以"模型 vs 信号函数"是伪二选一；真正该问的是：**这个 state 值不值得存在**。
- **规则不可被模型取代的地方**：候选域定义必须稀疏、可解释、可审计（`state_mask` + 逐条命中明细）。
- **模型该上的地方**：域内排序，且必须过上面的三条件测试。
- **更值得投入的方向**：仓库自己的事件研究已经指出**正 edge 事件是"涨停"**（+1.30%/5d、+0.68%/10d），
  而突破（donchian 20 日通道 +0.00%/−0.56%）与"低位反弹确认"（−0.50%）都是**负 edge**。
  ⇒ 应该**顺着已验证的正 edge 事件扩策略**（limit_momentum 方向），而不是给负 edge 状态配更强的模型。
- **对现有 sleeve 的含义**：`donchian_breakout` 与（若启用）低位反弹腿在事件研究里都是负 edge，
  应按同一协议做**降级评估**（保留为 research 或直接关闭），把预算让给有正 edge 的腿。

## 34. 2026-10-01 追加：块级预算硬约束（`sleeve_total_max`）+ 输出 schema 容错

### 34.1 问题（§33.4 记录的两个缺口）

`budget.share` 与 sleeve 的 `max_weight` **只约束 forced 名称**；非 forced 的 `signal_candidate`
权重由优化器给出 —— 所以一条声明 0.05 的腿实际能吃下 30% 的账面（10/01 实测）。

### 34.2 实现

1. **`apply_sleeve_block_cap()`**（模块级、可单测）：把"卫星块（非 model 通道）"的总权重压到 cap 以内 ——
   缩卫星 → 余额按各模型名的 cap 余量补回 → 补不进的部分**留现金**（宁可少投，也不让预算声明失效）
   → 缩放后买不起一手的卫星名清零并记账。
   **缺 `last_close` 时不做 lot 判断**（否则会把整本账清空 —— 单测踩到过）。
2. **接线**：`_repair_unfillable_targets(..., sleeve_total_max=...)`，在权重定稿前执行；
   结果写入 `lot_summary.sleeve_block_cap`（实测出现在 pipeline report：
   `{"applied": true, "cap": 0.075, "sleeve_weight_before": 0.0, "reason": "within cap"}`）。
3. **cap 取值**：显式 `[selection.portfolio_constraints].sleeve_total_max` 优先；
   否则 `gross × (1 − model_min_share)` = 0.75 × 0.10 = **0.075**。
4. **输出 schema 容错**：落盘前补齐 `selection_channel`（默认 `model`）与 `selection_sleeve`（默认空），
   修掉"没有信号腿贡献时下游按列名读取 KeyError"。

### 34.3 顺带修掉的两个真实缺陷

- `_attach_lot_columns`：缺 `last_close` 时 `pd.to_numeric(None)` 退化成标量 → 后续 `.to_numpy()` 抛
  `AttributeError`（写单测时触发，属潜伏缺陷）。
- `apply_sleeve_block_cap(cap=None)`：先前先 `float(cap)` 再判空 → `TypeError`。

## 36. 2026-10-01 追加：9/30 全链路实跑 + 组合塌成 2 只的根因（整手 vs 槽位预算的算术冲突）

### 36.1 一键链路实跑（9/30 决策日）

```
daily_bars 739s → moneyflow 441s → features 844s → clean_panel 1829s → model_scores 35s
```

### 36.2 结果：只有 2 只（不是 6 只）

| 代码 | 权重 | 通道 | 模型分 | 排名 | 收盘 | 手数 |
|---|---|---|---|---|---|---|

gross **66.9%**（低于目标 75%），卫星块 0%。

### 36.3 根因：不是可买性、也不是权重方案，是**算术放不下**

候选池 8 只（预选 `preselection_model_slots=8`），逐只一手市值与账户占比：

| 代码 | 收盘 | 一手市值 | 占 45k |
|---|---|---|---|
| 300820.SZ | 64.97 | 6,497 | 14.4% |
| 301448.SZ | 50.91 | 5,091 | 11.3% |
| 301297.SZ | 47.70 | 4,770 | 10.6% |
| 688222.SH | 44.69 | 4,469 | 9.9% |
| 600391.SH | 40.61 | 4,061 | 9.0% |
| 301230.SZ | 38.48 | 3,848 | 8.6% |
| 300151.SZ / 002674.SZ | 19.82 | 1,982 | 4.4% |

**8 只各买一手 ≈ 32,700 元 = 72.7%**，但优化器还要给头部分数更高的名字更多权重 →
修复循环先 `lifted_for_lots`（8 只全部抬到一手）→ 再 `dropped_for_lots`（连丢 6 只）→ 只剩 2 只、gross 66.9%。

**对照实验（同一决策日，只改权重方案）**：`alpha_power 2.0→1.0` → 仍 2 只（gross 63%）；
`weighting rank_power→equal` → 仍 2 只（gross 62%）。**⇒ 与权重方案无关，是"一手=最小仓位"与"槽位预算"的冲突。**

### 36.4 两种修法（需要选一个）

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（配置级，快）** | 把价格上限调回**槽位可买**口径：`equity×gross/slots/lot_size` = 45000×0.75/6/100 = **56.25 元** | 重新排除 57~86 元的票（回到用户当初想放开的区间） |
| **B（机制级，推荐）** | 在组合层引入**"一手=最小仓位"约束**：`min_weight_i = one_lot_value_i / equity`，再按 `min(gross/min_weight, max_holdings)` 决定持仓数并选人（例如 5~6 只、每只 12~15%） | 要改优化器/修复循环；但这是唯一能把"更宽价格区间"和"满仓 6 只"同时成立的路径 |

配套：无论 A/B，都应在**入池前**剔除"一手 > 单槽预算"的票（而不是让修复循环事后逐个剔），
否则每次都会出现"抬到一手 → 又放不下 → 丢票"的级联。

### 36.5 顺带修掉的两个护栏 bug（都是自己加的东西反过来咬人）

1. `pk --trade-date` 的"同决策日预选文件"护栏里用了 `pd`，但 `scripts/run_cn_pipeline.py` **顶层没有 import pandas**
   （各函数内局部导入）→ `NameError` 被 `except Exception` 吞掉 → 误报"日期不匹配"，把回放挡死。
   已补局部 `import pandas as pd`。
2. 同一处的 `except` **静默吞异常**（把"日期不匹配"这种误判变得无从查起）→ 已改为打印
   `[pk][warn] 回退判定异常: <类型>: <信息>`。

## 37. 2026-10-01 追加：持仓数区间 [2, 6] + 少数持仓时把 gross 用满

### 37.1 用户口径

> 最少可以只持有两只，最多 6 只。

据此不再需要 §36.4 的方案 A（把价格上限收回到 56.25 元），也不强求 6 只；
但要补两件事：**硬下限**（不能塌到 1 只）与**少数持仓时 gross 用满**（2×35% = 70% < 75%）。

### 37.2 实现

配置（`[selection.portfolio_constraints]`）：
```toml
min_holdings = 2                 # 硬下限：少于 2 只时按模型分从被剔名字里补回（记录 topped_up_for_min_holdings）
max_weight_concentrated = 0.45   # 少数持仓时的集中度上限（覆盖 regime 的单名上限）
```
`_repair_unfillable_targets()` 内新增（权重定稿前）：
1. **下限补位**：`live_count < min_holdings` 时，按模型分从原始候选池补回名字，权重 = 一手市值/equity，
   从现有持仓按比例腾额度；若腾完不足一手则跳过该名（记录 `topped_up_for_min_holdings`）。
2. **集中度部署**：当 `持仓数 ≤ gross/单名上限`（即 0.35 的上限让 gross 用不满）时，
   有效上限 `cap_eff = max(regime 单名上限, min(max_weight_concentrated, gross/持仓数))`，
   先按比例放大、再把余额**贪心填**给还有余量的名字，直到 `gross` 用满或所有名字触顶。
   **关键**：集中度上限是**显式覆盖** regime 上限，不能用 `min()` 削（首版就栽在这里：
   `min(0.35, 0.375) = 0.35` → `scale=1.0` → 一行没动）。
3. 审计字段 `concentrated_deploy = {gross_cap, n_live, effective_cap, invested, scale, applied}` 写入 `lot_summary`。

### 37.3 实测（9/30 决策日，同一候选池）

| 改动后 | 2 | 301448 **37.5%** / 301230 **37.5%** | **75.00%** |

`concentrated_deploy = {"gross_cap": 0.75, "n_live": 2, "effective_cap": 0.375, "invested": 0.6693, "scale": 1.0714, "applied": true}`

**9/29 回归（4 只）**：仍为 600909(21.8%) / 002708(19.4%) / 300139(18.1%) / 301230(15.7%)、gross **75.00%**
→ 新逻辑对"已经投满"的账是 no-op ✓。两者都能买整手（`lot_fillable=True`）。
