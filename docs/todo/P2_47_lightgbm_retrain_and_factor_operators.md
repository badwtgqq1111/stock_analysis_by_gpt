# P2.47 两个问题的直接回答：LightGBM 要不要"实时训练"？因子是不是"算子的排列组合"？

编写：2026-10-11。用户问：（1）"lightgbm 是不是改成实时训练更好呢，现有的是保存成模型。"
（2）"因为 lightgbm 不就是给每个因子一个动态权重么。因子 是不是 用算子（加 减 乘 除 log 等等）
因子通过不同的算子做排列组合，开发新的因子？"
关联：`P2_45`（LightGBM 差距定位）、`P2_46`（参考书评审）、`P1_25`（LLM 因子挖掘）、`P2_40`（上线闸门）。

## 0. 先纠一个事实：我们**不是**"保存了一个模型就不管了"，但**也真的没有在重训**

查了产物与每日流程（不是猜）：

| 证据 | 读出来的事实 |
|---|---|
| `output/models/cn/lightgbm/alpha_zoo_hk/model.txt` mtime = **2026-09-27 09:33** | 最近一次训练是 9 月 27 日（约两周前） |
| `model_manifest.json`：`train_start = 2025-09-29`、`train_end = 2026-05-06`、`validation_days = 60`、`embargo_days = 20`、`split.method = purged_time_split` | 训练窗口 **365 天**，窗口在 **5 月 6 日**就结束了；purged 切分**已经有**（单折，不是多折 walk-forward） |
| `feature_count = 90`（`[model_features] admission_mode = "apply"`） | 模型只吃**准入后的 90 个因子**（"先筛后塞"这步是对的） |
| `run_daily_production.sh` 的 `STAGES`：`features / clean_panel / model_scores(★false) / preselection / pk / …` | **训练阶段（`lightgbm/transformer/cnn`）根本不在每日流程里**；每日只做 `model_scores`＝**用保存的模型打分** |
| `extra.params.objective = "regression"`（MSE） | 点损失，不是排序目标（对应 P2.46 评审里"立刻可抄"的第 3 条） |

**结论**：你说的"实时训练"，在我们这里是**真的缺**：模型文件是 9-27 训的，训练数据窗口结束在 **5-06**。
而规则类策略（rot_arm / box_arm / 多因子）**每天都在重算** —— 这本身就是"模型看起来跑不过传统策略"的
一个结构性原因：一边每天更新，一边用两周前（数据截止 5 月）的模型。

## 1. 但要分清楚三种"实时"，只有第 2 种值得做

| 形态 | 做法 | 判断 |
|---|---|---|
| ① 在线逐笔增量学习 | 用 `init_model` 续训 / 流式更新 | **不做**：LightGBM 没有真正的在线增量；金融噪声上续训极易漂移；且没法做 parity 与回滚 |
| ② **周期性滚动重训（推荐）** | 每周（或每 N 个交易日）用滚动窗口 + purged/embargo 重训一版，**先进影子，过闸门才切生产** | **要做**：这才对应"模型不过时"。我们有影子组合 + `promotion_check.py` 做落地判断，缺的只是"重训的节奏与触发条件" |
| ③ 漂移触发的条件重训 | 由数据漂移/IC 衰减/换手异常触发（书 Ch 26.3 drift detection） | **补做**：作为②的补充，而不是替代 |

**为什么不日频重训**：日线 + 20 日前瞻标签下，相邻两天的训练样本几乎完全重叠（书 **Ch 7.2 p.196** 的"有效样本量"：
SPY 10 年 248,436 名义观测 → 有效 **11,830**，约 **4.6×** 高估）。天天重训 ≈ 用几乎同一批样本重排一遍，
边际信息极少，却把"训练-推理一致性"和"回滚"变难（每天一个模型，出问题找谁？）。
**重训频率再高也救不了三件事**（P2.45 的清单）：**标签不是超额**、**窗口太短**、**决策链改写排序**。所以顺序必须是
**先 B/C（标签+窗口）→ 再 A（同口径回放）→ 最后才是②③（重训节奏）**。

## 3. 第二个问题：LightGBM 是"给每个因子一个动态权重"吗？

**不是。** 这是把**线性模型**的直觉套到了树上：
* **线性融合才是"权重"**：`score = Σ wᵢfᵢ`。我们仓库里对应 `llm_sleeve_oos_backtest.py` 的
  `base_v1`（25 列 IC 加权）、`llm_new`（LLM 因子集 ICIR 加权）、`combo_50_50`（z 分等权）。
* **LightGBM 是"分段常数 + 条件分裂"**：每次分裂只问"某个因子是否大于某阈值"，叶子给出一个常数预测。
  所以它学到的是**区间化的、条件化的**规则（"动量>0.03 且 PE<15 → 加分；动量>0.03 但 PE>30 → 不加"），
  **没有"每个因子一个权重"这种东西**；同一因子在不同区间方向/强度都可以不同 —— 这正是非线性的来源。
* 书里也明确：**原生特征重要性不可靠**（Ch 12.2 p.337），要看**交互**得用 **SHAP dependence / interaction**
  （Ch 11.4 / 12.5）。我们已经把 SHAP 接到了选股归因页。
* 所以「LightGBM = 动态权重」只对**线性那一层**成立；树的增量价值在**分段与交互**，不在权重。

## 4. 第二个问题：因子是"算子的排列组合"吗？

**是，而且我们已经在做** —— 只是做成了**有预算、有门槛的符号搜索**，不是无脑排列组合：

* **算子白名单**（`scripts/llm_factor_mining.py:ALLOWED_FUNCS`，14 个）：
  `abs / log / log1p / sqrt / sign / clip / where / rank / shift / rolling / mean / std / min / max / zscore`，
  四则运算与比较写在**表达式树**里；安全求值 `safe_eval` 禁 dunder / import / 未来函数（用 `shift` 显式控时点）。
* **真实产物**：`zscore(rev_1m) - zscore(vol_20)`（反转×低波动，`rev_vol`：IC 0.0993 / ICIR 0.683 / NW t 5.00）、
  `zscore(pe_pb_combo) * -1 + rank(rps_20)`（估值反向 + 强势排名，maxρ 0.96 被判冗余）。
* **三条纪律**（书里给的是同一条：Ch 7.4 p.204 "搜索记账"，5 标签 × 3 阈值 × 10 变体 = 150 组合
  ⇒ 即使全是噪声也**期望 7~8 个假阳性**）：
  1. **安全求值**（已做）；2. **多重检验预算**（BH-FDR + HLZ t≥3 + DSR 试验台账，已做）；
  3. **经济解释与冗余**（`max|ρ| ≤ 0.7`、同簇只留代表，已做）。
* **边际空间在哪**：`factor_ic_registry.csv` 的 1,366 列里 **900+ 本来就是"别人组合好的"**
  （Alpha101 / GTJA191 / Alpha158 / TA-Lib）。所以继续"排列组合"的收益主要在三处：
  **① 跨层交互**（量价 × 资金流 × 财务，如 `moneyflow_amount / vol_20`）；
  **② 条件化**（按 regime / 波动分箱的因子，对应评审第 5 条"条件 IC"）；
  **③ 新数据源**（资金流、龙虎榜、宏观、公告）。
  **提高组合数量本身不是策略**（每多搜 150 个组合就多 7~8 个假阳性）。

## 5. 一句话总结

* **重训**：不是"要不要实时"，而是"**周期性滚动重训 + 影子 + 闸门**"；前提是先修标签与窗口，否则重训只会更快地过拟合。
* **权重**：LightGBM **不是**权重机器（那是线性融合的活）；它是**分段 + 交互**机器，看交互要用 SHAP。
* **算子**：因子确实是算子的排列组合，我们已经在跑**符号搜索**；真正稀缺的不是"组合的数量"，而是**新数据源 + 跨层交互 + 条件化 + 严格的多重检验预算**。
