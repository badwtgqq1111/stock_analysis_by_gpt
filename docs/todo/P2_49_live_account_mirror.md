# P2_49 实盘镜像账户（真实持仓接进系统）

> 触发（2026-10-12，用户提问）：**"截图是我的现有持仓，是做到模拟盘，还是再单开一个实盘模拟。"**

## §0 结论（一句话）

**单开一个「实盘镜像」账户**：`output/paper_trading/live_mirror/`，与策略模拟盘
（`output/paper_trading/account/`）**并列但分账**，只共用同一份执行假设
（`config/execution_assumptions_cn.json`）。不把真实持仓并进策略模拟盘。

## §1 为什么不并进现有模拟盘

| 维度 | 策略模拟盘 `account/` | 实盘账户（截图） |
|---|---|---|
| 起点 | 空仓 45,000（2024-09 建账） | 未知，只能从快照反推 ≈45,237.75 |
| 标的来源 | 当日最终名单（`paper_selection_history.csv`） | 人工决策：4 只持仓 + 3 笔已清仓 |
| 口径 | 前向：T+1 开盘成交、扣佣金/滑点/印花税、整手、建模涨跌停/停牌/退市 | 持仓盯市（不重放建仓，买入日期未知） |
| 用途 | 回答"照着名单下单会怎样" | 回答"我的持仓模型怎么看 / 离模型有多远" |

并账的代价是**实打实的**：曲线会在快照日出现一次无解释跳变，之后无法再和影子变体做
"同窗口逐期配对"（本仓库判定任何改动的唯一判据，见 `promotion_check.py`）。
换句话说，并账会同时毁掉两条口径。

## §3 关键口径（三条，都写在产物里）

1. **累计收益的分母 = 推算初始本金** `= 持仓成本 + 现金 + |已实现亏损|`。
   已实现亏损已经体现在账户价值里，不加回去分母就变小、亏损率被说轻。
   实测：39,208.80 + 40.55 + 5,988.40 = **45,237.75** → 累计 **−13.33%**。
2. **快照日之前不回填**。真实买入日期未知，回填等于编数据。曲线从快照日起逐日累积，
   `< 30` 观测一律自报 `short_sample`；策略池里**不给它编曲线**（`tracking=insufficient_history`）。
3. **盯市价源**：盘中用腾讯批量实时价（`live:<时间戳>`）、盘后/离线用日线收盘；
   没有价的票**保留快照价**并标 `snapshot`，不填 0、不外推。

## §4 逐票建议规则（R0~R5，机械可复算）

```
R0 在最新生产最终名单里且 rank<=3      → 买入
R1 在最新生产最终名单里                → 持有
R2 只在候选池（没拿到权重）            → 持有（观察）
R3 两处都不在 且 20 日动量为负         → 卖出
R4 两处都不在 但 20 日动量非负         → 持有（降级观察）
R5 缺日线数据                          → 持有（数据不足，不给动作）
```

规则写死在 `ADVICE_RULES`，每行产物都带 `rule`/`reason`，任何人可以拿快照复算；
与 LLM 逐股多空分析（DeepSeek，K 线页）是**两条独立证据**，不互相替代。

## §7 同轮顺手修的两处前端小 bug（K 线自选实时快照）

现场复核（13:45 交易时段）时发现并修掉，都已复验：

1. **来源标签误标「延迟」**：`quoteLabel()` 只认 `tencent/eastmoney/live`，而腾讯批量快照返回的
   `source` 是 **`tx_quote`** ⇒ 51 行实时价全被打成「延迟」（照实标注的方向没错，但判据错了）。
   改为按已知实时源前缀判定。
2. **行内时间戳冻住**：`v-memo` 键只有 价/涨跌/来源，而 title 带更新时间 ⇒ 价格没动的行永不重渲染
   （实测 title 停在 13:43:46）。改为 title 显示**行情自带时间** + 把 `quote.time` 加进 memo 键。

复验（Playwright，间隔 8 秒两次）：`实时 · 13:45:45` → `实时 · 13:45:54`，**advancing=true**，
85 行 / 51 行有实时价、0 控制台报错 ⇒ 顺带关掉上一轮清单里"13:00 后复验"那条。

## §8 实盘页（2026-10-12 第二轮，用户："这个 web前端没有体现呢？"）

上一轮只把持仓接进「模拟盘」页与 K 线自选；这一轮**独立成页** `/live`（导航「图表 / 回测 → 实盘镜像」）：

| 块 | 内容 | 数据源 |
|---|---|---|
| ① 账户概览 | 总资产 / 推算初始本金 / 累计 / 浮盈 / 已实现 / 第一重仓 + 同窗 20 日 | `/api/paper` 的 `live` |
| ② 持仓 + 个股行情 | 点一行 → **实时分时（今日，30 秒轮询、时段与可见性门控）** 或 **日K（365 根烛台 + 均线）** | `/api/intraday/{code}`、`/api/stocks/{code}/ohlcv` |
| ③ 收益对比 | **日 / 周 / 月** 三个粒度 × 近 1 月 / 3 月 / 1 年 / 3 年，组合 vs **中证500** 双线 + 8 列统计 | `/api/paper/live/performance` |
| ④ 收益日历 | 日 / 周 / 月三种格子视图（红涨绿跌、悬停看基准与超额） | 同上（`calendar` 字段） |

口径纪律（写在页面与产物里）：
* ③④ 是**回填口径**：按**当前权重**在窗口起点买入持有（不含现金、已实现、成本）——
  「这一篮子现在这个结构过去 N 年跟中证500 比怎样」，**不是账户业绩**；账户业绩只从快照日向前累积。
* 三个粒度的累计必须**完全相等**（同一段行情的不同切法）：早期实现用 `nav末/nav首−1` 漏掉第一期，
  日频 −19.46% 被算成周频 −17.90% → 改为**期收益复利连乘**，并加不变式测试防复辟。
* 实测（2026-10-12）：近 1 月 +1.09% vs −4.23%（超额 +5.32pp）、近 3 月 +1.98% vs −10.90%（+12.88pp）、
  近 1 年 −38.83% vs −1.70%（**−37.13pp**）、近 3 年 −19.46% vs +27.85%（**−47.31pp**）。

## §9 盘中实时 + 每日自动刷新（2026-10-12 第三轮，用户："实盘的 要求每天数据都是实时更新的"）

拆成三件可验证的事：

1. **盘中实时**：新接口 `GET /api/paper/live/realtime`（2 秒 TTL）+ 纯函数 `realtime_view()` ——
   用腾讯批量快照把持仓价换成实时价，再走**同一套 `account_state` 算术**（市值/权重/浮盈/推算初始本金/
   累计/集中度/当日参考盈亏）。页面 15 秒轮询（交易时段）/120 秒兜底（非交易时段），
   逐行显示行情自带时间，缺价退回盘后价并计入 `unpriced`（不填 0）。
   * 为什么复用 `account_state`：账户算术只能有一份实现，盘后那份与页面那份各写一套迟早对不上。
   * 顺手把「当日参考盈亏（现价 vs 昨收）」做出来 —— 与券商 App 首页那个数同口径，可直接对上账。
2. **盘后自动刷新**：每日自动化 `DAILY_LIVE_MIRROR`（排在 `ai_picks` 之前）重写 nav / positions /
   summary / **performance.json** / 选股源 CSV / 名单归档；新鲜度体检由 1 项扩到 2 项
   （「实盘镜像」+「实盘镜像收益对比」），落后会在当日日志与通知里点名。
3. **收盘价接管**：官方收盘价入库后，盯市那行不再用盘中价（`nav_price_source` 字段自报口径）；
   否则 nav.csv 会永远留着一个盘中价（实测：asof 当天的合成行会盖掉官方收盘）。
