# P2.59 收益日历排错行 + 分时面板缺股票标头（附：一个会卡住预检的测试切片陷阱）

用户两条反馈（2026-10-13）：
1. "20261012 号 不是星期一么？这个日期是不是排错了啊"（收益日历，实盘镜像页）
2. "K 线选股 点中某只股票的时候，分时线看不到股票标头呢"

---

## 一、收益日历：日期确实排错了（2026-10-12 落在「六」列）

**现场**（Playwright 量 DOM，同一构建；修复前复现见验收包 `check_calendar_alignment.txt`）：

```
== 2026-10   表头：一 二 三 四 五 六 日
     ·   ·   ·   8   9  12   ·        ← 12 落在「六」，实际是周一
   ❌ 2026-10-12 在「六」列，实际是周一
全月合计：167 个格子错位
```

**根因**：`LiveAccount.vue` 的 `calendarBlocks` 只在**月初**补一次空格（`pads` =
该月第一个交易日是周几），之后**按顺序填充**格子 —— 而格子只有**交易日**，
周末与节假日缺席 ⇒ 后面的日期整体左移。9 月（周末缺口）和 10 月（国庆 + 周末）都能看到。

**修法**：每个格子按**自己那天是周几**显式占列（`grid-column`），缺口自然留白：

```ts
function weekdayCol(period: string): number {           // 周一起算，1..7
  return ((new Date(`${period}T00:00:00`).getDay() + 6) % 7) + 1
}
// 模板：:style="{ ...cellStyle(cell), gridColumn: String(cell.col) }"
```

修复后 **0 个错位**（2026-10-12 回到「一」列，8/9 所在行留白到周日）。

## 二、分时面板：加上「股票标头」

K 线页点自选里的一只票 → 展开「当日分时」面板，**面板里看不出这是哪只票**（页面顶部的
K 线标头早已滚出视野）。实盘镜像页的「当前」pill 也只有代码、没有名称。

**修法**：
* `KlinePage.vue` 的「当日分时」面板新增 `.intraday-head`：
  `代码 · 名称 · 最新价 ±涨跌幅 · 行业·板块·分时标的 · 时段`；

实测（Playwright 点自选第一行）：
`✅ 分时标头：300229.SZ 拓尔思 13.23 +0.76% 软件服务 · 创业板 · 分时标的 09:30 → 15:30`

## 三、顺带修掉：一个**会卡住每日预检**的测试切片陷阱（重要）

`test_daily_script_safety.py` 从 `run_daily_production.sh` 里**抽一段脚本出来执行**，抽法是：

```python
body = source[source.index("run_data_step() {"):
              source.index('if [ "${DAILY_DATA_REFRESH:-1}" = "1" ]; then')]
```

它把"下一个 if 的文本"当结束标记。P2.56 恰好在这两者之间插入了「基准指数同步」与
「**当日数据就绪闸门**」两段 ⇒ 抽出来的 body 里包含了闸门调用，于是：

* **14:00 之后**跑预检：闸门要等当日中继数据，最多**阻塞 45 分钟**（实测 10 分钟仍未返回）；
* 若闸门判定"未就绪"，harness 会走到 `notify_alert`（harness 里没定义）⇒ 退出非 0 ⇒ 测试失败
  ⇒ **18:30 的每日生产会在预检阶段被自己的测试挡住**（比卡住更糟：看起来像"代码坏了"）。

**修法**：按**大括号匹配**取函数体（`name() {` → 第一个顶格 `}`），并断言切片里不含
`daily_ready_gate` / `DAILY_BENCHMARK` / `DAILY_DATA_REFRESH` 等其它段落关键词；
新增 `test_function_body_extraction_is_scoped` 防止边界再漂。
修后该文件 7 passed / **0.06s**（此前要么 45 分钟、要么误判失败）。
