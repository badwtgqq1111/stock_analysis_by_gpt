## 1. ① 月份：日历与迷你条共用**一条时间轴**

日历页早就把视图状态写进 URL + `localStorage['selection_calendar_state_v1']`；K 线的迷你条
却自己记一份 ⇒ 从日历点票进 K 线会跳回"最后一根 K 线所在月"，刚看的那个月丢了。

改成同一份状态（`composables/selectionLabels.ts` 里 `readSharedMonth / writeSharedMonth`）：
优先级 **显式 `?month=` → 日历存的月 → 最后一根 K 线所在月**；翻月写回 `?month=` 与那份
localStorage；日历的 `gotoStock()` 现在带上当前月 + 选中日。

**踩过的坑（实测）**：换票时先把 `miniMonth` 置空、再等 K 线数据回来重算 —— 中间存在
`miniMonth === ''` 的窗口，此时点「最新」会走 `days[last] || ''` 分支**什么都不做**
（实测"最新"停在 2026-08）。另外把空月写进 localStorage 会把日历存的月份**清掉**。
现在：换票直接写入（要跟随 query 就跟随，否则保持当前月），clamp 负责兜底，空值一律不写。

## 2. ② 自选侧栏悬停摘要：批量接口 + 复用同一张卡

自选 150+ 行，逐行 `/api/stocks/{code}/bundle` = 150 个请求（每个还要读估值/财务/龙虎榜）。
新增 `GET /api/calendar/by-code?codes=...&limit=3`：只读台账一列，按 code 分组一次返回
`n / n_sources / first_date / last_date / mean_excess_r5 / rows[最近 N 条]`，并回 `as_of`
（台账最后决策日）让界面能自证口径；上限 400 只/次（`requested` 如实回）。

前端 `composables/useSelectionSummaries.ts`：模块级缓存（台账一天只更新一次，跨页面复用）、
200 只/批、300ms 防抖（分组名单是**逐组陆续到达**的，不防抖会按增量发 13 个请求）。
卡片复用 `SelectionDetailCard.vue`，新增 `show-dates`（行跨多个决策日时把日期列出来）
与 `code`（每行的决策日可点进 K 线）—— 这样侧栏与 K 线浮层的文案只有一处实现。

**接口的诚实边界**：`rows` 里的 `r5/excess_r5` 是**决策日之后**的收益，最新决策日必然为空
（前瞻窗口没走完），卡片因此显示「待结算」而不是 0；`as_of` 一起返回，避免"拿旧台账当今天"。

## 3.5 图上明细卡与行情 tooltip：两个都要显示，且不重叠（第九十九轮，用户两轮反馈）

**第一轮反馈**："悬停内容重叠了" —— 明细卡与「涨跌/振幅/成交量」tooltip 叠在一起（两者都贴光标），
卡片里 `T+5 超额 −0.87%` 还折成两行。
**第一版修法走错了**：让行情 tooltip 给卡片让位（卡片显示期间隐藏 tooltip）—— 用户看过后明确否掉：
"改完之后，只显示新的了…**要两个都显示啊**"。

**最终做法**（`KlineChart.vue` + `SelectionDetailCard.vue`）：
1. **摆位避让** `placePop()`：每次显示/换日在 `nextTick` 里拿两个**真实矩形**摆卡片 ——
   ① 贴命中区（时间轴那条 28px）正上方、左边界跟随记号；② 撞上 tooltip 就挪到**光标对角角**
   （光标在右半图 ⇒ 卡片去左上，反之去右上）；③ 再撞就换另一侧的下方。卡片不出图区（四边各留 8px），
   宽度按真实宽度夹（固定 330px 估宽会让长策略名越界）。
2. **不隐藏任何一方**：删掉第一版的 tooltip early-return；tooltip 每次移动后让卡片重排一次。
3. **底部命中区也补行情 tooltip**：指针不在画布上时 crosshair 不参与 ⇒ `onHitEnter()` 手动
   `fillTooltip(dp)` 并钉在图区左上角（位置固定，不会把卡片挤走）。tooltip 字段填充因此抽成
   `fillTooltip()`，十字光标与命中区共用一处口径。
4. **卡片内部不折行**：`.ms-pop-head/.ms-pop-row` 加 `flex-wrap: nowrap` + 子项 `white-space: nowrap`
   （根因：flex 子项默认可被压得比内容还窄）。

**判据（`check_ui_hover_both_visible.py`，8 项全绿）**：K 线区三处高度悬停 → 卡片与 tooltip
**每次都同时存在**且**都不相交**；卡片不越界；每行单行；底部命中区悬停 → 两个也都显示；
移开 → 卡片收、tooltip 仍在；迷你条卡不回归；无控制台报错。
**边界**：这是"摆位"换来的同时可见，不是数学上的永不重叠；取位三档都被占住时退到最不冲突的一档
（z-index 卡片 30 > tooltip 20，真挤到一起时卡片在上、链接仍可点）。卡片不再跟光标走是刻意取舍。

### 3.1 行情读数：悬停才显示，但**固定停靠不压光标**（用户两轮反馈）

> 第一轮："鼠标把日期挡住了呢，另外 K 线图里没有直接看到股票代码/名称。"
> 第二轮："我还是想用悬停的方式显示，但是避开鼠标显示呢。"

两条要求合起来其实是"**悬停触发** + **位置不跟鼠标**"。做法是拆成两块：

```
┌ 左上·常驻身份条 ────────────────┐
│ 300229.SZ  拓尔思  12.830 −2.88% │   ← 只回答"这是谁"（标题栏滚走也看得见）
└──────────────────────────────────┘
                       （中间是 K 线，鼠标停在哪都不挡）
┌ 左下·悬停读数面板 ─────────────────────────────────────────────┐
│ 2026-01-16  开 26.700 高 27.130 低 24.900 收 25.140 −7.10% 振幅 8.24% 量 1.33亿 │
└────────────────────────────────────────────────────────────────┘
   ↑ 光标落到某根 K 线才出现；换一根 K 线=读数变、这个框不动；离开图区/落到价格轴即消失
```

* `bottom: 96px` 是刻意抬高的：贴着底边会压住成交量那一根（实测面板与量柱重叠），抬到量柱上方。
* `placePop()` 现在避让**两个**固定 UI（身份条 + 读数面板）：明细卡优先贴命中区正上方，
  与任一矩形相撞就换到光标的对角 —— 三者可以同屏且互不遮挡（Playwright 用真实 bbox 判相交）。
* 实现上 `hoverPanel.visible` 只在 `param.point && param.time && dataMap[time]` 同时成立时为 true，
  所以"没有 K 线的地方"不会留下上一次的读数。

## 5. 边界与"顺手发现"（不是本轮引入）

* **月份共用是单向优先**：`?month=` 显式指定时以它为准；从 K 线切回日历，日历也会读同一份
  localStorage，但如果它自己 URL 里带 `month=`，仍以 URL 为准。
* **侧栏摘要是"最近 3 条"**，不是"这个月的全部"；卡片标题写了台账总条数与首末日。
  想看某天全部 → 点该行日期（跳 K 线）或「当日全部 →」（跳日历）。
* **【已修·第九十九轮】策略名单刷新与当日日线同步的竞态**（原记录如下，修法见 §5.1）：2026-10-15 18:54 的
  `refresh_strategy_lists` 把 `jq_multi_factor_size_roe` / `jq_roe_roa_diagnostic` 记成
  `failed`，原因是 `select_jq_multi_factor.py` 用**中证500 基准的最新交易日**（10-15）
  当信号日，而当日日线（`assets/data/clean/ohlcv/.../year=2026`）当时还只到 **10-14**
  ⇒ `ValueError: No close bar on 2026-10-15`（`output/results_cn/strategy_lists/*.log`）。
  这条会让 `test/test_strategy_lists_contract.py::test_status_artifact_is_written_and_matches_config`
  变红（每日预检因此 rc=1，自动化被挡在门外）。与本轮 UI 改动无关；修法建议：
  信号日取"基准日 ∩ 最新收盘"，或让刷新器在"数据未就绪"时按 `no_signal`/重试处理 ——
  留给下一轮单独做（要连同 `test_strategy_lists_contract` 一起验）。

### 5.1 已修的竞态：信号日取"基准 ∩ 最新收盘"

`scripts/select_jq_multi_factor.py` 原来把信号日设成**中证500 基准的最新交易日**（10-15），而当日日线
要等流水线的 `clean_panel` 阶段才落地 ⇒ 那个窗口里直接 `raise ValueError("No close bar on 2026-10-15")`，
`refresh_strategy_lists` 把两条聚宽策略记成 `failed`，`test_strategy_lists_contract` 变红、自动化被挡在门外
（实测 18:54：`status.json` failed=2，clean 面板最大 10-14、10-15 行数 0）。修法：

```python
if target not in days:                     # 基准走在前头、当日日线还没到
    settled = days[-1]                     # 退到 ≤ 基准日的最后一个真实收盘日
    print("[jq] 目标日 … 还没有收盘日线 ⇒ 退到最近收盘日 …；名单日期会如实落后一个交易日")
    target = settled
```
并且 `main()` 用 `result["trade_date"]`（而不是入参 `day`）命名产物 —— 否则会出现"日志说退到 10-14、
产物却写 10-15"的假账（实测踩到）。修后两条各 20 只候选、rc=0、产物日期 = 2026-10-14。
